# Stud UI Clean Roblox

A complete, measured design system extracted from a shipped Roblox simulator (17 ScreenGuis, ~7,700 instances) plus a
**tested component kit** that rebuilds it from scratch. Your job when this skill triggers: produce UI that is
indistinguishable from the reference screenshots, by building through the kit instead of hand-placing frames.

Look at `assets/screenshots/` first (index in `assets/screenshots/README.md`). Screenshot 20 shows the original shop
(left) next to the same window generated by this kit (right) — that is the quality bar.

## What makes the style (keep these, they are the identity)
1. **3D stud buttons**: dark outline (ImageButton background) → darker *Biseau* lip at the bottom (the thickness) →
   *Face* CanvasGroup with a bright vertical gradient, two diagonal hard-edged glass streaks (one light, one dark),
   a tiled stud texture fading in toward the bottom-right, a double 1 px inner bevel and a 2 px bottom glow. No corners.
2. **Heavy outlined text**: only Montserrat Heavy (windows) and GothamSSm Heavy (HUD) (+ Montserrat Bold for
   descriptions). Every label has a Contextual stroke 2–4 px in a *dark tint of its background* (never plain black),
   and important labels are **extruded**: a dark copy 2 px below the white text.
3. **Dark glass windows**: colored stud header (or the pink shop header texture) with a 96 px icon overflowing the
   top-left corner rotated −10°, 50 px title, red chunky X; body = black at 50 % transparency with a thin white
   second frame; the world stays visible behind, blurred (18) with FOV +8.
4. **Sticker icons** from the bundled CheckUIIcons library, "… 1st Outline" variants, tilted −8°/−10°/−12°, overflowing.
5. **Dark item slots** with a spinning sunburst behind the icon, 3 px black border + light inner line, lime selection.
6. **Strict color semantics**: green = in-game money / confirm, purple = Robux / skip, red = shop / locked / destroy,
   blue = primary navigation, yellow/orange = premium / claim-all / restock, gray = done. Rarities Common → Cosmic.
7. **Pixel geometry + one UIScale**: everything in offset px for a 1050×620 screen, each root scaled by a `WindowScale`
   UIScale = clamp(min(vx/1050, vy/620), 0.52, 1.18). This keeps 1 px bevels and 4 px lips crisp on every device.
8. **Springy motion**: press 0.92 in 0.05 s, Back-Out release, bouncy open (0.86 → 1, 0.32 s), fast close (0.16 s),
   sunbursts always spinning, badges pulsing, a sound on every interaction.

## Workflow

1. **Identify the archetype** (layouts-and-archetypes.md §3): product-list shop, collection grid + tabs, reward calendar,
   upgrade/prestige, season pass, premium offers, reward banner, HUD element. Open the matching screenshot and example.
2. **Install the modules** in the place (once): `StudUI`, `StudMotion`, `CheckUIIcons` as ModuleScripts in
   `ReplicatedStorage` (or map `src/` with Rojo). If you can't write files into the place, inline the module source in
   your build script.
3. **Build in Edit mode** into `StarterGui` with a builder function like the examples (`return function(UI, Icons, parent) … end`),
   run once from the command bar / MCP `execute_luau`. Never rebuild UI on every spawn.
4. **Wire behaviour** with a LocalScript inside the ScreenGui (see `examples/06_MenuController.client.luau`):
   `Motion.Window`, `Motion.BindButton`, `Motion.SpinSunbursts`, feedback (`Motion.Float`, `Motion.Shake`).
5. **Verify visually**: screenshot and compare with the reference capture; walk `references/checklist.md`.

## Rules of thumb (with the reason)
- **Offsets, not scale** — the bevels are 1–4 px; scale sizes round them away. One WindowScale per root handles devices.
- **Build through the kit** — a hand-made flat button misses 9 of the 10 layers that make it read as 3D.
- **Tint every outline** — `#26020A` on red, `#022826` on blue, `#1A2402` on green… Pure black makes it look generic.
- **Extrude labels** — the 2 px dark copy under white text is what gives the "toy" depth; `UI.ShadowText` does it.
- **Never opaque windows** — black @0.5 + blur keeps the game world present; it's a simulator, the world is the reward.
- **Let things overflow and tilt** — header icons, tile icons, badges, "OP"/"VALUE!" stickers. Perfect alignment looks corporate.
- **Same component, different size for hierarchy** — the primary action is the bigger blue button, not a new style.
- **Keep the French instance names** (`Fenetre`, `Entete`, `Corps`, `Biseau`, `Face`, `Fond`, `Texte`, `Ombre`, `Icone`…):
  runtime scripts (recolor, tabs, disabled state, menu controllers) find parts by these names.
- **Motion is part of the style** — no menu should appear without the bounce, no button without hover/press, no sunburst static.
- Use exact icon paths from `references/icon-catalog.md`, "1st Outline" variants by default.

## Extending the style
New color theme for a button = 4 colors: a 3–5 stop bright `fond` gradient (lighter top), a 2-stop `biseau` ~45 % darker,
a near-black `bord` of the same hue, a very dark `texte` tint. New rarity = text gradient (light → saturated) + tab theme +
optional panel image. New window = pick the closest archetype and reuse its proportions; header color from `UI.HeaderThemes`
or a new 3-stop vertical gradient in the same luminance range. Keep corner radii ≤ 6 and stroke thicknesses in the table.

## Verifying with the Roblox Studio MCP
If the Roblox Studio MCP is connected: build with `execute_luau` (Edit), make the window visible temporarily (store and
restore the original `Visible`), `screen_capture`, compare with the reference screenshot, fix, then clean up any temporary
instances. For motion, `start_stop_play`, run a client check (blur 18, FOV +8, other GUIs hidden then restored), read
`get_console_output`, stop Play. Never leave test instances or changed properties in the user's place.
